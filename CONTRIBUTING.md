# Contributing

Keep changes focused and commit each coherent implementation/test/documentation step when complete. Do not backdate or fabricate development history. Use synthetic sources and observations in tests; never use a real conversation export, recording, personal profile, credential, home path or private log as a fixture.

Run the native deterministic suite, portable Windows suite and repository privacy guard. Native/cloud/audio tests are different evidence: state exactly what was run and what remains unverified. Avoid enabling paid inference or switching providers as error recovery. Preserve original text, attribution, branch identity, source references and user corrections.

For native audio changes, verify capture/stop/cancellation on real supported hardware after automated tests. For Windows changes, use the Windows build workflow and packaged smoke test, then test default microphone and playback routing on a physical machine. Do not advertise feature parity or universal screen-share invisibility.

Preserve the GPL-3.0 license and upstream SpeexDSP/Parrot notices. Include corresponding source and build instructions with distributed builds. Do not edit the vendored DSP source without a specific need.
